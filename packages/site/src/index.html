Outcome-first browser use

From an agent request to a deliberate browser action.

AgentTab makes the ordinary path clear: a task gets a workspace, the agent works in it, and people take over when an action needs them.

  1. 1

    Start in a task workspace

    A task opens or adopts an explicit tab. Ownership is visible and stays scoped to that task.

  2. 2

    Let the agent do the routine work

    Standard actions use the task workspace, not broad browser control.

  3. 3

    Take your turn when it matters

    Human handoff protects secret and other human-only input. Recognizable consequential actions wait for Commit.

Trust boundary

Local runtime, signed-in Chrome, bounded standard access.

What AgentTab does

  • Runs locally beside your signed-in Chrome profile.
  • Coordinates task-owned browser workspaces and visible handoff.
  • Stages recognizable consequential actions before they take effect.

What task ownership does not do

Task ownership is an execution and coordination boundary. It is not cookie, identity, or profile isolation.

Standard mode does not provide raw cookies, storage, passwords, arbitrary JavaScript, raw Chrome DevTools Protocol access, or coordinate actions.

!

The remaining risk is real

Web pages can contain prompt injection or attach an external effect to an innocent-looking control. Commit is a best-effort review barrier for recognizable actions, not a guarantee that every external effect is recognized. Review the page and the staged action before you proceed.

Private by architecture

Local only. No telemetry. No remote AgentTab service.

AgentTab does not collect, sell, or share personal data. Browser work happens through your local runtime and your own signed-in browser.
